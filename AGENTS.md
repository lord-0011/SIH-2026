# Development Workflow & Operational Rules

These 6 rules must be strictly followed for all development tasks in this repository:

1. **Feature Branch First**: Always create and switch to a new descriptive feature branch (`feature/<name>`) before starting any work.
2. **Implementation Plan & Approval**: Always provide a detailed implementation plan before editing or creating any code, and **never change or create code without explicit user approval**.
3. **Execute & Verify**: Make the approved changes and thoroughly verify/test them.
4. **Walkthrough**: Always provide a detailed walkthrough after completing changes, summarizing what was done and the verification results.
5. **Push & PR**: Commit changes, push the feature branch to `origin`, and create/provide the Pull Request link against `main`.
6. **Updated ZIP File**: After completing the task, create an updated `.zip` file of the project repository (excluding `.git` and build artifacts).
